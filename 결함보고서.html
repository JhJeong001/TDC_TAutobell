결함 상세 (Defect Details)

ISSUE-QR-01 P2 · High TC FAIL Jira 등록완료 QR 로그인 — WebSocket 미사용, HTTP 폴링 방식으로 구현됨
결함 분류기능 결함 (Functional Defect) — 요구사항 불일치
연관 TCTC_QR_NEW_05
발견 환경STG — auth.skt-id.co.kr/v2/login (QR 탭 활성화)
발견 일자2026-05-30 (초기 수행), 2026-05-31 (재수행 재현)
기대 동작wss:// WebSocket 프로토콜 연결 유지 확인
실제 동작
  • new WebSocket 생성자 0건 — JS 스크립트 16개 전수 분석
  • 폴링 방식: setInterval → POST /qr/verify/device 반복 호출
  • 초기 수행(05-30) 및 재수행(05-31) 모두 동일하게 재현
재현율100% (2/2회 재현, 안정적)
영향 범위QR 로그인 전 흐름 — QR 생성 ~ 인증 대기 구간 전체
Jira 티켓등록 완료 (2026-06-01)  Open
리스크 분석 (High)
HTTP 폴링은 기능적으로 동작하나, WebSocket 대비 불필요한 서버 부하(매 interval마다 HTTP 요청 발생)와 응답 지연 가능성이 있습니다. TC 설계 기준이 WebSocket 사용을 전제로 작성된 경우, 현재 구현은 요구사항 불일치에 해당합니다.
조치 방향
1. 개발팀에 "WebSocket → HTTP 폴링 변경이 의도된 설계 변경인지" 확인 요청
2. 의도된 변경이라면: TC_QR_NEW_05 기대 결과 수정 → 이슈 Close
3. 미확인/설계 오류라면: WebSocket 방식 구현 수정 요청 → P1 상향 검토

결함 분류UI/UX 결함 — 정보 미노출 (미확정, 수동 재확인 필요)

기대 동작QR 코드 만료까지 남은 시간을 MM:SS 형식으로 화면에 표시
실제 동작
  • 페이지 내 MM:SS 패턴 텍스트 미노출
  • QR 코드 렌더링(.qrcode-img) 정상 ✅
  • 만료 시 dim 처리(.dimmed 클래스) 정상 ✅
  • 만료 후 자동 갱신(clearInterval 후 재요청 패턴) 정상 ✅
추정 원인JS 렌더링 시점 차이 — 자동화 스크립트 실행 타이밍에 타이머가 아직 DOM에 삽입되지 않았을 가능성 (환경 이슈 복합 가능성)
재현율자동화 기준 2/2 미노출 / 수동 육안 확인 미실시 — 미확정
영향 범위QR 만료 타이머 노출 — UX 혼선 가능성 (서비스 중단 수준 아님)
Jira 티켓미등록  수동 확인 후 등록 예정
리스크 분석 (Medium)
타이머가 실제로 미노출이라면 사용자가 QR 코드 유효시간을 알 수 없어 UX 혼선 발생 가능. 다만 QR 만료·갱신 로직 자체는 정상이므로 서비스 중단 수준의 결함은 아닙니다.
조치 방향
1. 수동 테스트 우선: 실제 브라우저에서 QR 탭 진입 후 타이머 텍스트 육안 확인
2. 미노출 재현 시: 프론트엔드 버그로 Jira 등록 (P3 유지)
3. 정상 노출 확인 시: 자동화 타이밍 이슈 → TC 검증 방법 조정 후 Close

    [즉시] ISSUE-QR-01 개발팀 확인 요청

    [단기] ISSUE-QR-02 수동 재확인 후 Jira 등록
    실제 브라우저에서 QR 탭 진입 후 타이머 텍스트 육안 확인. 결과에 따라 Jira 등록(P3) 또는 자동화 TC 조정 후 Close 처리.
  • 3
    [중기] 모바일 테스트 환경 구축
    NA 5건(TC_QR_NEW_01~04, 06)은 실물 모바일 기기 미확보로 인한 환경 이슈. 실기기 테스트 환경 또는 에뮬레이터 연동 방안 검토 필요. 해당 TC는 QR 로그인의 핵심 시나리오(앱 연동)를 검증하므로 커버리지 확보 필요.

    [지속] 결함 메트릭 모니터링
    현재 실행 가능 TC 기준 결함 발견율 66.7% — 높은 수치. QR 로그인 기능의 추가 TC 설계 및 회귀 테스트 자동화 강화 권장.
